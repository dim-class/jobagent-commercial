# JobAgent Commercial · ローカル AI 転職活動支援ツール

[日本語](README.md) | [简体中文](README.zh-CN.md)

JobAgent Commercial は、求人情報の収集、履歴書との適合度分析、応募準備、選考状況の管理、
面接・Offer の振り返りまでをローカル環境で支援する AI 転職活動ツールです。

履歴書や応募履歴はローカルの SQLite に保存され、API キーはバックエンドプロセスだけが読み取ります。
AI は候補を整理して提案しますが、応募するかどうか、何を送るか、最終的に送信するかは必ず本人が決めます。

> 初めてインストールする場合や、別の PC で試す場合は [SETUP.md](SETUP.md) を先に参照してください。
> 詳細な技術仕様、開発履歴、API 一覧は[中国語版の完全ドキュメント](README.zh-CN.md)に残しています。

## 主な特徴

- **ローカルファースト**：履歴書、求人、分析結果、応募履歴をローカル SQLite に保存します。
- **履歴書解析**：PDF、DOCX、TXT をローカルで解析し、スキル、資格、職歴などを構造化します。
- **複数の求人取り込み方法**：手動入力、コピー＆ペースト、スクリーンショット、可視ブラウザー、Chrome 拡張 POC に対応します。
- **AI 適合度分析**：求人と現在の履歴書を比較し、0～100 点、判定、強み、不足スキル、リスク、応募用の短いメッセージ案を生成します。
- **応募キュー**：AI の提案を見たうえで、応募、後回し、スキップを本人が選択します。
- **選考管理**：応募、返信、面接、Offer、辞退・不採用を時系列で記録します。
- **HR コミュニケーション支援**：受信内容を手動で取り込み、質問の整理と編集可能な返信案を作成します。自動送信はしません。
- **分析機能**：応募経路、履歴書バージョン、面接、Offer、戦略の傾向を決定論的に集計します。
- **Offer 比較**：本人が設定した重みと評価を使い、計算過程を開示した比較表を作成します。AI は使用しません。
- **Windows 向け起動方法**：開発環境用スクリプトに加え、ビルド済みフロントエンドを FastAPI から配信する起動方法も用意しています。

## 安全方針

JobAgent は、次の操作を標準機能として行いません。

- 無人・バックグラウンドでの応募
- 複数求人への一括応募
- 自動的な初回メッセージや追加メッセージの送信
- CAPTCHA、ログイン保護、レート制限、その他の安全対策の回避
- 求人サイトのパスワード、Cookie、localStorage の外部送信
- 本人の確認なしでの応募ステータス変更

グローバルな自動応募モードはありません。実験的な M6 フローを有効にした場合も、対象は 1 求人だけで、
BOSS 直聘が生成する初回メッセージを JobAgent では事前確認できないことを理解したうえで、
2 回の本人確認後に 1 回だけ「立即沟通」を試行します。自動再試行、後続メッセージ、バッチ実行は行いません。

## システム概要

```text
履歴書 PDF / DOCX ──► ローカル解析（AI 不使用）──► 構造化プロフィール

求人票の手動入力      ──┐
クイック取り込み      ──┤─► 正規化 + 重複判定 ──► 求人データベース
コピー / 画像         ──┤
ブラウザー取り込み    ──┘

求人 + 履歴書 ──► JobMatchAgent ──► AI 推薦（0～100 点 + 判定 + メッセージ案）
                                      │
                                      ▼
                              応募キュー（本人が判断）
                                      │
                                      ▼
                       返信 → 面接 → Offer（すべて手動記録）
```

## クイックスタート

リポジトリのルートディレクトリで、PowerShell から順番に実行します。

```powershell
.\scripts\dev.ps1 setup
```

```powershell
.\scripts\dev.ps1 seed
```

```powershell
.\scripts\dev.ps1 start
```

起動後、<http://127.0.0.1:5173> を開きます。

- `setup`：Python 仮想環境、バックエンド依存関係、フロントエンド依存関係、Playwright を準備します。
- `seed`：ローカルデータベースを作成し、実在しないデモ求人を登録します。
- `start`：バックエンドとフロントエンドを別々の PowerShell ウィンドウで起動します。

通常利用では、ルートディレクトリの `Start-JobAgent.cmd` をダブルクリックできます。
すでにサービスが動作している場合は既存プロセスを再利用します。停止するには `Stop-JobAgent.cmd` を使用します。

バックエンドを変更しながら開発する場合は、リロードを有効にします。

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\launch-console.ps1 -Reload
```

## OpenAI 互換 API の設定

API キーはアプリの「设置 → AI 接口」から保存できます。ファイルを直接編集したり、保存後に再起動したりする必要はありません。
OpenAI のほか、OpenAI 互換 API を提供するサービスの API URL とモデル名も設定できます。

キーはバックエンドが参照する `.env` にだけ保存されます。

- 開発環境：プロジェクトルートの `.env`
- パッケージ版：`%LOCALAPPDATA%\JobAgent\.env`

API キーはデータベース、ログ、React フロントエンド、API レスポンスには含まれません。
キーを設定していない場合もアプリは起動でき、求人管理、履歴書管理、戦略ページなどの無料機能を利用できます。

主な環境変数：

| 変数 | 既定値 | 説明 |
| --- | --- | --- |
| `OPENAI_API_KEY` | 空 | AI 分析に必要 |
| `OPENAI_MODEL_FAST` | `gpt-5.6-luna` | 通常・一括分析用モデル |
| `OPENAI_MODEL_SMART` | `gpt-5.6-terra` | 明示的な高品質再分析用モデル |
| `DATABASE_URL` | `sqlite:///./data/jobagent.db` | SQLite の接続先 |
| `MAX_ANALYSES_PER_RUN` | `50` | 一括分析 1 回あたりの上限 |
| `AUTO_APPLY` | `false` | 互換用。グローバルな自動応募機能はありません |
| `HUMAN_CONFIRMED_APPLY_ENABLED` | `false` | M6 の求人単位・二重確認フローを表示するか |
| `REPORT_TIMEZONE` | `Asia/Tokyo` | 日次指標のタイムゾーン |

モデル ID は設定から読み取り、コードに固定していません。

## 基本的な利用手順

1. **履歴書を登録**
   PDF、DOCX、TXT をアップロードします。解析はローカルで実行され、AI は呼び出しません。
2. **求人を取り込む**
   求人票を手動入力するか、「快速采集」からコピーした文章・スクリーンショットを取り込みます。
3. **内容を確認する**
   会社名、職種、勤務地、給与、経験年数、学歴、求人票本文を本人が修正できます。
4. **AI 分析を実行する**
   現在の履歴書と転職戦略をもとに適合度を分析します。同じ入力の結果はキャッシュされます。
5. **応募キューで判断する**
   元の求人ページを開き、応募するかどうかを本人が決めます。
6. **応募後に記録する**
   実際に使用した履歴書を選び、「标记已投递」でローカル記録を更新します。
7. **返信・面接・Offer を記録する**
   選考の進行に合わせてイベントを追加し、後から分析できる状態にします。

## 求人の取り込み方法

### 1. クイック取り込み（推奨）

普段使用している Chrome / Edge で求人ページを開き、表示内容をコピーして JobAgent の「快速采集」へ貼り付けます。
文字をコピーできない場合は PNG / JPG / WebP のスクリーンショットも利用できます。

この方法では JobAgent がブラウザーを操作せず、Cookie やログイン情報も読み取りません。
クリップボードは「读取剪贴板」をクリックした瞬間に 1 回だけ読み取ります。

### 2. 可視ブラウザー取り込み

Playwright 管理の独立ブラウザープロファイルを使用します。対応サイトやページ構造によって取得できない場合があります。
ログイン、CAPTCHA、追加確認は本人が可視ブラウザーで処理します。

### 3. Chrome 拡張（POC）

普段使用している Chrome で開いている BOSS ページから、本人が拡張ボタンを押したときだけ構造化情報を読み取ります。
自動検索、自動ページ送り、自動応募、Cookie の読み取りは行いません。

詳細は [`extension/README.md`](extension/README.md) を参照してください。

## 応募・選考管理

JobAgent は次の状態とイベントをローカルに保存します。

- 未処理、確認済み、保存、後回し、スキップ
- 応募済み、返信あり、面接中、Offer、不採用
- 応募時に使用した履歴書バージョン
- HR とのやり取りとフォロー予定
- 面接プロセスと各ラウンドの結果
- Offer の改訂、交渉内容、受諾・辞退・失効・撤回

状態変更は追記イベントとして記録されます。すでに同じ状態の場合は重複イベントを作成しません。

## 分析機能

AI を使わない決定論的な集計として、次の分析を提供します。

- 応募経路・都市・職種ごとの返信率や面接率
- 履歴書バージョンごとの転換状況
- 面接ラウンドごとの進捗と結果
- Offer の条件変更と交渉履歴
- 本人の重み付けによる Offer 比較

サンプル数が少ない場合は「样本不足」と表示し、確定的な提案を出しません。
統計は相関を示すだけで、因果関係を保証しません。

## Offer の比較

複数の Offer を比較する場合、本人が次の情報を入力します。

- 給与、賞与、福利厚生、勤務地、働き方、成長性などの重み
- 各 Offer に対する 1～5 の主観評価
- 必須条件と自分で設定した為替レート

JobAgent は各項目の「得点 × 重み = 寄与」を表示します。情報の網羅率が基準未満の場合は総合結論を出しません。
外部為替 API は使用せず、比較結果を保存したスナップショットは後から入力値を変更しても変わりません。

## データベース移行

データベース構造は Alembic で管理しています。旧バージョンから更新するときにデータベースを削除する必要はありません。

```powershell
.\scripts\dev.ps1 migrate
```

`setup` と `seed` も必要な移行を自動実行します。

## テスト

拡張のビルド、バックエンドテスト、フロントエンドの本番ビルドをまとめて実行します。

```powershell
.\scripts\dev.ps1 test
```

Chrome 拡張の隔離 E2E テスト：

```powershell
.\scripts\test-extension-e2e.ps1
```

テスト用 fixture はプロジェクト内で作成した架空データであり、実在する求人ページの複製ではありません。
AI 呼び出しはモックされ、通常のテストで有料 API や実在する求人サイトへアクセスしません。

## 既知の制約

- 求人サイトの仕様変更により、ブラウザー取り込みや拡張のセレクターが動作しなくなる場合があります。
- 自動化されたブラウザーへの表示を拒否するサイトでは、クイック取り込みを使用してください。
- スクリーンショットからの抽出は、画像の品質や特殊フォントによって精度が低下します。
- 画面に表示されていない求人票部分は拡張から取得できません。
- AI の適合度は応募結果を保証しません。応募前に求人票と生成内容を本人が確認してください。
- 求人サイトの利用規約、アクセス頻度、応募条件は利用者自身で確認する必要があります。

## プライバシーとコンプライアンス

- 履歴書本文と応募履歴はローカルに保存します。
- モデルへ送信する内容は、構造化した概要と分析に必要な抜粋に限定します。
- API キー、Cookie、パスワードをログやデータベースへ保存しません。
- スクリーンショットは解析後に破棄し、画像本体をデータベースへ保存しません。
- URL を記録するときは、セッショントークンを含む可能性があるクエリ文字列を除去します。
- 将来追加する求人サイトアダプターも、本人ログイン、安全機構を回避しないこと、サイト規約と頻度制限を守ること、収集と応募を分離することが必須です。
