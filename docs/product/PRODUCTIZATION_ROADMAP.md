# JobAgent 产品化路线：从个人工具到任何人可用

## 产品定义

JobAgent 是本地优先的求职 Agent。用户上传自己的简历、设置求职偏好，在正常浏览器中登录
招聘网站后，由本地扩展执行有界搜索和采集；岗位统一进入 canonical job intake，AI 只负责
可解释匹配建议，投递与账号状态变化始终由用户逐项确认。

“任何人可用”不等于把一台电脑上的数据库做成多人共享。第一阶段仍是一人一机、一份本地
数据库；每位用户安装自己的实例，简历、岗位与浏览器会话互相隔离。

## P0 — 首次使用与通用偏好

当前进度（2026-08-31）：已增加首次设置页和后端搜索能力声明；控制台的城市与岗位方向已改为
读取本机用户策略，不再写死个人搜索值。运行时策略已迁到 gitignored 的 `data/`，发行模板为空，
既有本机策略已按内容哈希保全。下一步是完成空数据安装与现有用户升级验收。

验收：

- 空数据库启动后有清晰的首次设置页；
- 用户可以上传 PDF/DOCX/TXT 简历；
- 用户可以设置目标城市、岗位方向和技能，而不看到原开发者的个人偏好；
- 搜索页只读取已保存策略，不再写死北京或云平台；
- 未完成简历/岗位方向/城市设置时，搜索 fail closed 并给出可操作提示；
- 既有用户的简历、岗位、策略和历史事件升级后不丢失。

## P1 — 身份阶段与通用匹配

验收：

- 明确支持“在校/应届、社招、有经验岗位也可、全部”候选阶段；
- 该设置贯穿搜索卡片过滤、详情预览、canonical intake 与历史岗位清理；
- 不允许只改前端开关而扩展仍按旧规则过滤；
- 职业类别、技能同义词与负面关键词来自用户配置，不来自开发者职业背景。

## P2 — 可安装发布包

当前进度：P2B 已能用锁定的 PyInstaller 构建**未签名 Windows x64 便携候选包**，包含 Python
后端运行时、已构建 React 前端、迁移、中性策略和固定版本 MV3 扩展；产物审计、文件清单与 ZIP
SHA-256 均已加入。EXE 启停、首次初始化、升级前 SQLite/策略备份和启动失败自动恢复已在隔离目录
实测。它仍不是签名安装器，也没有在完全没有开发工具链的独立 Windows VM 上验收。

验收：

- Windows 安装器或签名的便携包包含后端运行时和已构建前端，不要求用户安装 Python/Node；
- 首次启动自动创建本地数据目录和用户策略，不写入源码目录；
- 提供启动、停止、升级、卸载和保留/清除数据的明确选择；
- Chrome 扩展有固定版本、升级说明和兼容性检查；
- 升级前自动备份 SQLite 与策略，失败可回滚。

## P3 — 平台适配层

验收：

- BOSS 只是一个 adapter；平台无关的 SearchPlan、Job、匹配、复核和事件模型保持唯一；
- 每个平台声明自己的搜索、详情、薪资和身份能力，缺失能力明确降级；
- 不使用凭据提取、CAPTCHA 绕过、stealth、指纹伪装或私有接口；
- 平台 DOM 变化只影响对应 adapter 与 fixtures，不复制 persistence/dedup pipeline。

## P4 — 隐私、可靠性与支持

验收：

- 设置页可导出/导入加密或明确标注的本地备份；
- 一键诊断只输出非敏感版本、健康状态与错误码；
- 日志不包含简历正文、聊天正文、cookie/token、页面安全参数或 API key；
- 新用户路径、空状态、断网、无 Key、未登录、验证页和升级路径都有端到端测试；
- 文档区分免费本地功能、可能产生费用的 AI 功能与需要人工完成的浏览器动作。

## 当前边界

- 当前是 P2B 未签名候选：普通运行路径不需要源码 Python/Node，但发布仍缺代码签名、安装/卸载
  UX 和无开发工具链的独立 Windows VM 验收，不得对外宣称正式可安装版。
- 当前 BOSS 城市代码只接受本地明确验证过的映射；未知城市 fail closed，不猜测、不调用
  BOSS 私有接口。
- P1 候选阶段设置已贯穿 SearchPlan 快照、扩展预览/导入与既有岗位队列视图。
- 自动批量投递、后台无人值守投递、自动招聘方消息与验证码绕过不属于产品化目标。
